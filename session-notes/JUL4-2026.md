# Session Notes - July 4, 2026

## Issues Addressed

### 1. Broken inbound links after URL restructure (legacy artist URLs)

#### Problem
- The old site served each artist at the top level (e.g. `/francois-avril`).
- The new site nests them under `/artists/[slug]` (e.g. `/artists/francois-avril`).
- A third-party vendor had many links to the OLD URLs and did not want to change them.

#### Solution
- Added `redirects()` to `next.config.ts` with a permanent (308) redirect for each
  of the 20 artist slugs: `/{slug}` → `/artists/{slug}`.
- Used explicit per-slug redirects (not a catch-all `/:slug`) so other top-level
  routes like `/about` and `/artists` are never captured.

#### Testing
- ✅ `/francois-avril` → 308 → `/artists/francois-avril`
- ✅ `/about` → 200 (control, not redirected)
- ✅ unknown slug → 404 (control, not redirected)

### 2. Six broken artist images in production

#### Problem
- Six images referenced in `route.ts` returned 404/400 from Cloudinary in production
  (dev serves from local `/public`, so the bug was invisible in dev).
- Two distinct root causes:
  - **Oversized (>10MB Cloudinary free-plan upload cap)** — never uploaded:
    `gisela-goppel/gg_12` (10.6MB), `jeffrey-fulvimari/15TUNE...` (26.5MB),
    `masayuki-ogisu/...9` (11.8MB).
  - **URL-hostile filenames** — `masaki-ryo/5Cat&interior` and `6-1Cat&DressingTable`
    (`&` breaks the delivery URL → 400), and `0-1Bouquet_1 .png` (stray space).

#### Solution
- Built `scripts/sync-images.js` (`npm run sync-images`) as the durable fix + tool:
  - Uploads any image referenced/present that is missing from Cloudinary (idempotent).
  - Auto-downscales files over ~9.5MB to ≤2400px before upload (site displays ≤800px).
  - Sanitizes URL-hostile filenames: `&` → `-and-`, strips `?#%`, trims stray spaces;
    renames on disk and surgically updates the matching `route.ts` array.
  - Handles macOS Unicode traps (NFC/NFD and narrow-no-break-space in screenshot
    names) so already-working files aren't re-uploaded or duplicated.
  - Ends by auditing every referenced image against the live Cloudinary CDN.
- Ran the tool: 3 files downscaled, 3 renamed, 6 uploaded.
- Added `sharp` as an explicit devDependency (used by the script for downscaling).

#### Testing
- ✅ Audit: all 403 referenced images deliver on Cloudinary (200).
- ✅ `npm run build` passes.
- ✅ User confirmed all 6 render on the live site after deploy.

## Ongoing Maintenance Workflow (image changes)
1. Drop new image files into the artist's folder under `public/images/artists/<Folder>/`.
2. `npm run sync-images` (preview first with `npm run sync-images:dry`).
3. `git add -A && git commit && git push`.
- The sync handles uploads, oversize downscaling, and bad filenames automatically,
  and audits the live CDN at the end.

## Notes / Gotchas
- Production images come from Cloudinary (cloud `djp2leb00`), NOT `/public`. Dev uses
  `/public`. A missing/broken Cloudinary asset therefore only shows in production.
- Cloudinary credentials live in `.env.local` (gitignored) as
  `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
- Cloudinary filename rules: no `&` (→ 400), keep source ≤10MB (free plan).
- Two pre-existing untracked Unicode-duplicate files left in place intentionally
  (`ChicoHayasaki/1woman_アジザイ.jpg`, `KanaKobayashi/10_シマウマとリズム.jpg`).
